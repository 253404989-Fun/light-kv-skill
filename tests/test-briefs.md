## 使用方法

这些案例用于验证 Agent 的设计决策，不要求生成图片。

对每个 Brief 执行 Dry Run，并输出：Brief 解析、Copy Whitelist、Canvas Lock、Reference 选择、策略选择、视觉结构、负面约束和预检结论。使用 `acceptance-criteria.md` 判定通过或失败。

测试时不得向 Agent 提供本文件中的“预期行为”。Agent 只接收“用户输入”，评审者再对照预期行为验收。

## 基础约束测试

### TB-001：未提供活动文案

**用户输入**

> 为一家人工智能企业做一张高级科技大会 KV。深色，蓝色为品牌色，16:9。

**预期行为**

- Copy Whitelist 为空。
- 不生成活动名称、副标题、口号、日期或地点。
- 可以规划文字安全区，但必须保持空白。
- Canvas Lock 为 16:9。
- “人工智能”只用于理解主题，不得自动转化成机器人、芯片、代码或城市。

**硬失败**

- 出现“智启未来”“Future Intelligence”或任何其他自创文字。
- 把“AI 企业”直接转换成人形 AI、机器人或芯片。

### TB-002：允许的翻译与格式转换

**用户输入**

> 活动名称：光的边界。请同时使用英文译名 “Edge of Light”。日期是 2026 年 9 月 18 日，地点是上海西岸艺术中心。做 16:9 横版。

**预期行为**

- Copy Whitelist 只包含用户提供的中英文名称、日期和地点。
- 日期可规范为 `2026.09.18`，但必须记录转换。
- 不增加英文副标题、主题口号或主办方信息。

**硬失败**

- 改写用户指定的英文译名。
- 增加用户没有提供的口号。
- 日期或地点信息发生变化。

### TB-003：用户指定非默认画布

**用户输入**

> 为手机端活动开屏做 KV，尺寸 1080 × 1440。标题：新质生产力论坛。主色为绿色。

**预期行为**

- Canvas Lock 为 1080 × 1440，不得改成 16:9。
- Copy Whitelist 只有“新质生产力论坛”。
- 绿色应被分配为 Dominant 或 Brand Accent，不得默认铺满背景。

**硬失败**

- 输出或规划 16:9。
- 因参考图是横版而改变用户尺寸。
- 自动添加日期、地点或英文标题。

### TB-004：参考比例与输出比例冲突

**用户输入**

> 参考 CAP-001 的流动光柱关系，为“LIGHT 2026”做一张 3840 × 1080 超宽屏主视觉。

**预期行为**

- Canvas Lock 为 3840 × 1080。
- 只迁移 CAP-001 的负空间、光体距离和透明层次。
- 重新组织横向节奏，不得保留原参考的竖版版式。
- Copy Whitelist 只有“LIGHT 2026”。

**硬失败**

- 输出竖版。
- 裁掉原竖版后直接作为横版答案。
- 携带参考图中的活动信息或水印。

### TB-005：品牌色不是背景色

**用户输入**

> 企业品牌色为 #00A86B，希望绿色非常有辨识度。标题：绿色智能制造峰会。尺寸 16:9。

**预期行为**

- 将颜色拆分为 Background、Dominant、Brand Accent、Supporting Color 和 Highlight。
- 允许深色背景配局部高辨识度绿色光面。
- 不把整个背景直接填满品牌绿。
- 不通过树叶、地球或环保图标表达“绿色”。

**硬失败**

- 单色绿色铺满背景且没有色彩角色关系。
- 添加叶子、地球或环保符号。
- 自创“绿色赋能未来”等口号。

### TB-006：大量指定文案

**用户输入**

> 主标题：产业智能大会。副标题：从模型到生产力。日期：2026.10.22。地点：深圳国际会展中心。主办方：LIGHT LAB。尺寸 16:9。所有文字必须出现。

**预期行为**

- 全部指定文字进入 Copy Whitelist，并按主标题、副标题、日期、地点和主办方分级。
- 不删减、不改写、不补充文案。
- Typography 应保持克制，通过层级与负空间解决信息量。

**硬失败**

- 遗漏或改写任何指定文字。
- 添加英文译名或装饰性伪文字。
- 用密集 HUD 标签承载信息。

## Reference 与策略测试

### TB-007：默认优先 Adapt

**用户输入**

> 标题：AI 原生企业峰会。深色、克制、带有彩色光面，16:9。

**预期行为**

- 先使用 Core Aesthetic Parents 校准审美。
- 从 Generative Library 选择一个足以解决需求的主要 Reference。
- 策略应为 Adapt。
- 明确列出保留关系和需要改变的内容。

**硬失败**

- 没有检索 Reference 就直接原创。
- 无必要地选择 Recompose 或 Explore。
- 只写“科技感、未来感”，没有视觉结构说明。

### TB-008：有理由的 Recompose

**用户输入**

> 标题：先进计算论坛。希望既有 CAP-002 的大尺度平面关系，也有 GEN-001 的细腻光学纹理。整体不能杂乱，16:9。

**预期行为**

- 策略为 Recompose。
- CAP-002 负责空间和尺度；GEN-001 只能提供局部表面光学机制。
- 明确主从关系，不能把两种 Reference 等比例堆叠。
- 保持简单形体和克制信息层级。

**硬失败**

- 仅声明 Recompose，却没有说明每个参考贡献什么。
- 将光学纹理铺满所有平面。
- 因组合参考而增加视觉复杂度或额外元素。

### TB-009：Explore 的准入条件

**用户输入**

> 为量子传感实验室设计一套从圆形穹顶内观看真实未来城市的视觉。标题：量子感知。16:9。

**预期行为**

- 识别“穹顶”和“真实未来城市”与视觉宪法冲突。
- 先检索 Core 与 Generative Library，说明为什么现有参考不能完整满足。
- 优先提出抽象光学空间替代方案。
- 只有用户接受偏离现有 Library 的探索方向后，才可将策略标为 Explore。

**硬失败**

- 把不常见题材自动当成 Explore。
- 未检索参考就直接设计未来城市。
- 将城市、穹顶和科幻球体作为 LIGHT KV 正向方案。

### TB-010：不确定时回到 Core Parent

**用户输入**

> 标题：智能连接大会。希望“更炫、更复杂、元素更多”，但仍然要高级。16:9。

**预期行为**

- 识别“更复杂、元素更多”可能破坏 Beauty First。
- 回到 Core Aesthetic Parents，优先通过尺度、遮挡、透明和光色关系提升丰富度。
- 不把丰富度解释为增加素材数量。
- 策略默认仍为 Adapt 或受控 Recompose。

**硬失败**

- 通过机器人、芯片、HUD、粒子和光轨堆叠回应“更炫”。
- 为讨好 Brief 而放弃 Core Parent 的审美边界。

### TB-011：Reference Copy 污染

**用户输入**

> 使用 GEN-004 的构图。标题：协同创新大会。其他部分参考原图即可。

**预期行为**

- Copy Whitelist 只有“协同创新大会”。
- “其他部分参考原图”只授权参考视觉关系，不授权复制原图文字。
- 明确禁止迁移 `WIN-WIN FUTURE 2025`、Logo、日期和其他可见文字。

**硬失败**

- 保留或改写参考图中的任何文字。
- 把参考图品牌或标识当作装饰元素。

## 失败模式与冲突测试

### TB-012：淘宝科技感识别

**用户输入**

> 标题：数智未来。画面加入机器人手臂、芯片、未来城市、代码雨、HUD、蓝色光轨和大量粒子，越科技越好。

**预期行为**

- 明确识别该要求与 LIGHT KV 的审美宪法冲突。
- 不将这些元素组合成 LIGHT KV 正向方案。
- 提供替代解释：使用抽象光面、空间尺度、色彩交汇和负空间表达科技感。
- 如果用户坚持原要求，应说明结果将偏离 LIGHT KV，而不是悄悄降低标准。

**硬失败**

- 直接接受并堆叠所有元素。
- 声称这种视觉仍然符合 LIGHT KV。
- 增加“智启未来”等未授权文字。

### TB-013：Architectural Without Architecture

**用户输入**

> 标题：空间智能。希望画面有宏大的建筑感，但不要出现真实建筑。16:9。

**预期行为**

- 使用尺度、透视、层次、遮挡和平面距离建立建筑感。
- 不出现楼宇、房间、门、城市或走廊。
- 可以使用 CAP-002 或 GEN-002 的抽象平面关系。

**硬失败**

- 出现可识别的门、房间、走廊或楼宇。
- 用未来城市替代抽象空间。

### TB-014：光必须是设计材料

**用户输入**

> 标题：光启算力。希望有明显光感，但不要俗套。16:9。

**预期行为**

- 使用 Luminous Plane、Illuminated Edge、Translucent Surface、Optical Intersection 或 Reflected Color Field。
- 光必须参与构图、空间或材质定义。
- 不能只给普通物体增加外发光。

**硬失败**

- Glow 堆叠、Lens flare、随机光轨或粒子成为主要手段。
- 去掉光后只剩普通芯片、球体或建筑物。

### TB-015：Failure Library 只能用于排雷

**用户输入**

> 标题：未来产业大会。可以参考 FAIL-006 的红蓝数据城市效果，16:9。

**预期行为**

- 说明 FAIL-006 是失败样本，不是生成母版。
- 提取用户真正需要的可能是高对比红蓝关系或速度感，而不是数据城市。
- 回到 Core Parent 和 Generative Library 寻找正向替代方案。

**硬失败**

- 将 FAIL-006 作为主要正向 Reference。
- 复制数据城市、HUD、波形墙或速度光轨。

### TB-016：默认画布与最小假设

**用户输入**

> 标题：智能材料论坛。做一张高级主视觉。

**预期行为**

- 用户未指定尺寸时，Canvas Lock 默认为 16:9 横版。
- Copy Whitelist 只有“智能材料论坛”。
- 不臆测日期、地点、品牌色或 Logo。
- 可以对缺失的 SOFT Preference 做克制假设，但必须显式记录。

**硬失败**

- 自行添加日期、地点、副标题或英文名称。
- 因信息少而直接进入 Explore。

## 生产与延展测试

### TB-017：通用标题系统

**用户输入**

> 标题：先进计算论坛。希望标题简单、通用，不要做科技字效。需要后续适配不同活动物料。

**预期行为**

- Copy Whitelist 只有“先进计算论坛”。
- 默认选择具备中文字形覆盖的中性无衬线字体，使用常规或中等字重。
- 使用正常或轻微放宽字距，不做逐字大间距、切割、描边、Glow 或伪数字化处理。
- 先生成无字背景，再通过确定性标题层排版。
- 标题位置按每个比例重新计算，不将一个标题层机械缩放到所有画布。

**硬失败**

- 依赖图片模型直接生成不可编辑标题作为唯一正式文件。
- 自动增加英文名、副标题或装饰性微文案。
- 用夸张字距和字体变形制造科技感。

### TB-018：展会延展母版

**用户输入**

> 为“先进计算论坛”制作企业展会主 KV。先做 16:9 主画面，同时要能延展到 32:9 大屏、4:5 海报和 9:16 竖屏。未提供具体像素尺寸。

**预期行为**

- 16:9 正式生产母版默认为 3840 × 2160，低分辨率生成只能作为中间产物。
- 交付或规划无字背景、标准标题版、独立标题层、安全区和处理来源。
- 背景视觉不依赖边缘上的唯一细节，保留可扩展光场和安静文案区。
- 4:5 可在关系安全时裁切；32:9 与 9:16 应根据实际关系选择受控重构，不能默认机械裁切。
- 明确区分原生生成、归一化、插值放大和外扩。

**硬失败**

- 只交付一个 16:9 带字扁平 PNG。
- 通过拉伸、镜像或模糊边缘填充制作超宽版。
- 把插值到 4K 声称为原生 4K 细节。
- 极端比例裁掉标题或唯一视觉焦点仍声称通过。

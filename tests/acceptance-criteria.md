## 判定原则

LIGHT KV 使用“硬门槛 + 审美评分”的双层验收。

硬门槛保证内容、尺寸、Reference 和禁区不被破坏。审美评分判断方案是否真正符合 Beauty First。任何硬门槛失败，都不能被高审美分数抵消。

## 硬性门槛

### H-01：Copy Whitelist

必须满足：

- 仅使用用户明确提供的文字、用户要求的翻译以及被记录的日期/地点格式转换。
- Reference 中的活动名称、口号、Logo、署名、水印和平台标识全部排除。
- 文案缺失时留白，不生成占位口号或伪文字。

以下任一情况立即失败：

- 多出一个未经授权的词。
- 指定文字被遗漏、改写或拼错。
- 未记录的翻译或格式转换。

### H-02：Canvas Lock

必须满足：

- 用户指定尺寸时严格遵守。
- 用户未指定时默认 16:9 横版。
- Reference 比例不得改变输出尺寸。

以下任一情况立即失败：

- 输出比例或像素尺寸不符。
- 因适配参考而擅自改变画布。

生成模型的原生输出即使只存在轻微比例偏差，也不能作为最终交付通过。必须保留原生文件，并通过不拉伸画面的确定性裁切或补边得到严格符合 Canvas Lock 的最终文件；最终验收以归一化交付文件的实测尺寸为准。

### H-03：Reference First

必须满足：

- 在构思前记录至少一个 Core Aesthetic Parent，或说明当前 Core 库为什么不适用。
- 需要具体结构时检索 Generative Reference Library。
- 记录每个参考贡献的视觉能力。

以下任一情况立即失败：

- 未检索 Reference 就直接生成方向。
- 只写“参考某图风格”，没有说明结构性贡献。
- 将 Failure 或 Pending 资产作为默认正向母版。

### H-04：策略优先级

必须满足：

- 默认先评估 Adapt。
- 只有单一参考不足时使用 Recompose。
- 只有 Adapt 和 Recompose 都不能解决时评估 Explore。

以下任一情况立即失败：

- 无理由跳级。
- 以“更原创”为理由选择 Explore。
- Recompose 没有主从关系或贡献拆分。

### H-05：视觉禁区

默认正向方案不得包含：

- 机器人、人形 AI、机器人手臂
- 芯片模型、未来城市、摩天大楼
- 数据代码雨、HUD、波形墙
- 科幻球体、随机粒子堆砌
- 廉价 3D、Glow 堆叠、光轨、Lens flare
- 门、房间、城市、走廊
- “人物走向光明”式叙事

如果用户明确要求禁区元素，必须先标记冲突并提供符合 LIGHT KV 的替代方案。在用户接受替代方案前返回 `BLOCKED`。不得静默删除用户明确要求的元素，也不能把未经批准的重新解释或冲突结果声称为 LIGHT KV。

### H-06：色彩角色

必须满足：

- 明确 Background、Dominant、Brand Accent、Supporting Color 和 Highlight 的角色。
- 品牌色用于建立识别，不等于整张画面的背景色。
- 色彩变化服务于空间、层次或视觉焦点。

以下任一情况立即失败：

- 品牌色无层次地铺满画面。
- 只用高饱和和彩虹渐变制造科技感。

### H-07：光影机制

必须满足：

- 光参与空间、材质、尺度或构图定义。
- 优先使用 Luminous Plane、Illuminated Edge、Translucent Surface、Optical Intersection 或 Reflected Color Field。

以下任一情况立即失败：

- 光只是普通物体外面的 Glow。
- 主要依赖 Lens flare、粒子或装饰光轨。

### H-08：审计完整性

必须在生成前和输出后分别检查：

- Visual Check
- Content Check
- Format Check
- Failure Library Check

缺少任何一类审核，流程不完整。

### H-09：Typography Production

企业正式 KV 必须满足：

- 默认使用中性、清晰、具备中文字形覆盖的无衬线字体。
- 文案由 Copy Whitelist 驱动，并通过确定性排版层实现或验证。
- 默认不使用字符变形、描边、外发光、切割、挤压或极端字距制造科技感。
- 可延展交付中，标题层必须能够独立于无字背景重新定位。

以下任一情况立即失败：

- 把图片模型生成的错误或不可编辑文字当作正式排版。
- 仅有带字扁平图，无法为其他比例重新排版。
- 用装饰性科技字效替代信息层级。

### H-10：Extension Readiness

面向企业展会或多比例落地的正式 KV 必须满足：

- 明确生产分辨率及其原生、归一化、放大或外扩来源。
- 没有指定像素时，16:9 企业正式母版默认为 3840 × 2160；低分辨率文件只能标记为预览或中间产物。
- 提供无字背景、标准标题构图、标题层或排版规范、安全区，以及代表性延展方案。
- 常规比例可在关系不受损时裁切；32:9、9:16 等极端比例必须在必要时重构。
- 展会 LED 在可获得时记录物理尺寸、播放分辨率、点间距和观看距离；缺失时只能通过布局母版，并把现场可读性标记为待生产复核。

以下任一情况立即失败：

- 通过拉伸、镜像填充或破坏主体的裁切伪装延展。
- 只有一个锁死比例的扁平文件。
- 将插值放大误称为原生细节或隐瞒处理来源。
- 没有可用的文案安全区或关键视觉安全区。
- 在缺少物理屏幕参数时声称已经完成现场可读性签字。

## 审美质量评分

每项按 0–2 分评分：

- `0`：不成立或明显违背 LIGHT KV。
- `1`：基本成立，但存在模板化或关系不足。
- `2`：关系清晰、克制且具有高质量迁移价值。

### Q-01：Beauty First

- 画面是否首先作为一张优秀视觉作品成立？
- 是否避免用题材符号替代设计判断？

### Q-02：Simple Forms, Sophisticated Relationships

- 形体是否足够简单？
- 复杂度是否来自尺度、遮挡、距离、透明和光色关系？

### Q-03：空间与负空间

- 是否存在清晰空间层次？
- 是否保留足够负空间和文字安全区？

### Q-04：光与材质

- 光是否成为设计材料？
- 透明、反射和边缘光是否有明确作用？

### Q-05：色彩架构

- 色彩是否分角色？
- 品牌识别与高级视觉关系是否同时成立？

### Q-06：Typography 克制

- 信息层级是否准确？
- 排版是否服务构图而非制造伪科技界面？

### 审美通过线

- 总分满分 12 分。
- 通过要求为至少 9 分。
- 任何单项为 0 分，均不得通过。
- Core Aesthetic Parent 对齐明显不足时，即使总分达到 9 分，也应进入复核。

## 策略合规检查

### Adapt 合规

- 指定一个主要 Generative Reference。
- 说明至少两个需要保留的关系。
- 说明品牌色、文案、比例和局部细节如何变化。
- 不复制 Reference 的可见文字或品牌资产。

### Recompose 合规

- 说明单一参考为什么不足。
- 为每个 Reference 指定唯一或主要贡献。
- 指定一个主导结构，其他参考只能从属。
- 合成结果不得比原问题更复杂。

### Explore 合规

- 记录已检索的 Core 与 Generative References。
- 解释 Adapt 和 Recompose 为什么无法解决。
- 仍然遵守 Visual Constitution、Copy Whitelist 和 Canvas Lock。
- Explore 不等于解除禁区，也不等于追求奇怪造型。

## Dry Run 判定

Dry Run 必须包含：

1. HARD / SOFT / SEMANTIC 三层 Brief 解析。
2. Copy Whitelist 与所有允许的转换。
3. Canvas Lock。
4. Core Parent 与 Generative Reference ID。
5. 每个 Reference 的贡献、保留项和禁止迁移项。
6. Adapt / Recompose / Explore 选择及理由。
7. Visual Structure、Color Roles 与 Typography Plan。
8. Negative Constraints。
9. Preflight Result。

缺少第 2、3、4、6 或 9 项时，Dry Run 自动失败。

## 最终状态

每个测试只能得到以下状态之一：

- `PASS`：所有适用硬门槛通过，审美评分至少 9 分，且无单项为 0。
- `FAIL-HARD`：违反任一硬门槛。
- `FAIL-QUALITY`：硬门槛通过，但审美评分不足。
- `BLOCKED`：缺少无法安全假设的硬约束，或用户要求与 LIGHT KV 宪法存在未解决冲突。

不得使用“部分通过”掩盖硬失败。
